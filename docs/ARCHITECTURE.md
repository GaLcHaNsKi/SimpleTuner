# Архитектура и технические решения

Источник требований — `spec.md`. Здесь описаны принятые решения и параметры первой реализации; критерии готовности остаются в ТЗ.

## Границы модулей

```text
app (Android, Compose, MVVM)
  ui/          экран, Canvas-индикатор, тема, анимации
  audio/       AudioRecord, выбор источника, отключение audio effects
  data/        SharedPreferences: только выбранный режим
  viewmodel/   StateFlow<TunerUiState>, lifecycle и переключение режима
      |
      v
core (Kotlin/JVM, без Android/Compose)
  domain/      эталоны, центы, кандидаты струн
  dsp/         YIN, RMS, confidence, фильтры и tracking
```

Пакет: `dev.simpletuner` (начальный applicationId, можно сменить до публикации).
DI — ручная композиция зависимостей, без Hilt/Koin. Один Activity, без Navigation.
SharedPreferences достаточно для одного enum; хранить стабильный ключ, не ordinal.
Обработка в `core/dsp` не зависит от Android; зависимости связываются вручную.

## Поток данных

AudioRecord → кольцевой PCM-буфер → RMS/проверка сигнала → YIN →
проверка уверенности/диапазона → медиана частоты → кандидат струны →
гистерезис/подтверждение → центы → StateFlow → Compose-анимация стрелки.

- Один владелец AudioRecord и последовательное управление start/stop/release.
- Blocking read вне Main; вычисления DSP вне UI. Не делать очередь задач на каждый read.
- Начать с одного последовательного worker для чтения и DSP, измерить бюджет.
  При нехватке времени разделить захват и DSP с ограниченным latest-only обменом
  заранее выделенными буферами и явным владением памятью.
- StateFlow содержит последнее состояние, не историю аудиофреймов.
- Не передавать буфер в другой поток, пока записывающий поток может его менять.
- Освобождение ресурсов в `finally`, обработка отрицательных кодов read,
  `ERROR_DEAD_OBJECT`, отзыва разрешения и системного отключения микрофона.

## Параметры DSP и ограничения

YIN с параболической интерполяцией минимума и анализом периодичности.
Mono PCM16: предпочтительно 48 kHz, fallback 44.1 kHz; окно 8192, hop 2048
(~42.7 мс при 48 kHz). Задержки и границы tau вычисляются по фактической частоте. 8192/48000 ≈ 171 мс — мало запаса
до цели 200 мс; накопление окна, read, DSP и фильтры измерять вместе.

Диапазон 35–400 Hz; tau задаётся от sampleRate и границ диапазона.
Нормализовать PCM в [-1, 1], удалить DC. Порог RMS, confidence, YIN threshold
подбирать по тестам, не привязывать к одному микрофону. Буферы переиспользовать.
YIN threshold — 0.08, порог RMS — 0.003, порог confidence — 0.92, медиана —
3 валидных измерения. Перед YIN используется усреднение и decimation в 4 раза;
его подавление aliasing и стоимость DSP требуют проверки на телефоне.

Сильная вторая гармоника проверяется отдельными тестами. Не исправлять октавные
ошибки безусловным делением частоты пополам: проверять кандидаты периода и
согласованность сигнала. При отсутствующей основной частоте физическая струна
может быть неоднозначна; низкая уверенность должна приводить к неопределённости.

## Определение струны и стабилизация

`nearestString` сейчас возвращает только математического кандидата в 35–400 Hz.
Это **не** подтверждение струны или состояния «Настроено».
Tracker дополнительно ограничивает расстояние до эталона ±150 центами;
порог подлежит проверке на реальном инструменте.

Параметры: медиана из 3 измерений, смена кандидата после 2 согласованных
измерений и преимущества в 20 центов; сброс при смене режима и после ~250 мс
без валидного сигнала. Проверить задержку, не складывать несколько длинных
временных фильтров. При подтверждённой смене струны старая медиана сбрасывается.

«Настроено» требует уверенного стабильного сигнала и |cents| ≤ 3. При выходе
за ±3 не оставлять статус из-за гистерезиса. Числовые центы не ограничивать;
лишь угол Canvas ограничивать ±50. Сглаживание UI не должно менять математику.

## Состояние экрана

Модель `TunerUiState`: выбранный режим + одно из взаимоисключающих
состояний `PermissionRequired`, `Starting`,
`Listening`, `Uncertain`, `Tracking`, `AudioUnavailable`.
`PermissionRequired` содержит признак постоянного отказа. Только `Tracking`
содержит частоту, струну, центы и признак стабильной настройки. На тишине/ошибке очищать актуальное измерение.
Не использовать комбинацию независимых boolean, допускающую ложное «Настроено».

## Android и UI

- Запрос RECORD_AUDIO при первом запуске, результат через Activity Result API.
- При постоянном отказе — встроенное пояснение и переход в настройки приложения.
- Запись привязать к RESUMED состоянию Activity; остановить до ухода в фон,
  отменить worker и освободить рекордер; возвращение идемпотентно.
- UNPROCESSED только после проверки доступности; fallback MIC при сбое.
- Отключать AGC/NS/AEC, если доступно управление; освобождать объекты effects.
- Обрабатывать занятый/отключённый микрофон, изменение маршрута и повторное
  разрешение без перезапуска приложения. Без фоновой службы.
- Canvas-шкала, Compose Animation API, системный duration scale, safe insets.
- На новых Android большие экраны могут игнорировать фиксацию ориентации;
  портрет — целевой режим телефона, адаптивность всё равно обязательна.
- Тексты в ресурсах, базовая русская локаль. Названия режимов в продукте
  «Гитара»/«Бас» (в ТЗ встречаются также Guitar/Bass).
- Масштабирование по доступной высоте/ширине; на очень большом шрифте допустим
  аварийный скролл для доступности, на типичных смартфонах он не нужен.
- Manifest: только RECORD_AUDIO. Аудио не писать на диск и не логировать.
